## Fix: touch buttons showing on desktop (Windows) screens

**Root cause** — `Touch.setVisible()` in `src/ui/Touch.ts:150` ignores the `enabled` flag. `Game.render()` calls it every frame with `state === PLAYING`, so the moment any desktop run starts, `#touchLayer` (the mobile FIRE / ADS / KNIFE / JUMP / RELOAD / PAUSE buttons) is un-hidden on pointer devices too. The layer also intercepts mouse input on its whole surface (stick/look handlers `preventDefault` every pointer event), so it isn't just cosmetic — it blocks gameplay clicks.

### Changes

1. **`src/ui/Touch.ts` — guard `setVisible`** (the fix):
   ```ts
   setVisible(on: boolean): void {
     if (!this.enabled) return; // a pointer device never has the layer, in any state
     if (this.visible === on) return;
     ...
   }
   ```
   This is the only hole: `showFirePrompt` / `setRotate` are already only reachable behind `touchEnabled` guards.

2. **`tests/e2e/smoke.spec.ts` — regression assertion** (this is what should have caught it): in the desktop `?test` boot section, right after the `gunVisible()` check, assert the layer is off:
   - `__NEON.touch()` reports `{ enabled: false, visible: false }`
   - `document.getElementById('touchLayer').hidden === true`

3. **AGENTS.md** — add one line to the Mobile/touch section: the layer's visibility is derived from `state === PLAYING` **and** `enabled`, so a disabled layer can never be un-hidden by the render loop.

### Verification
- `npm run check` (typecheck + lint + 264 unit tests)
- `npx playwright test tests/e2e/mobile.spec.ts` — must still pass (it drives the buttons via `?touch`, which forces `enabled` on)
- `npx playwright test tests/e2e/smoke.spec.ts` — must pass with the new no-buttons-on-desktop assertion

### Note
If your Windows machine is a **touchscreen laptop in tablet mode**, `pointer: coarse` detection may legitimately enable the touch layer on it — that's intended (it's a touch device). This fix guarantees plain mouse+keyboard desktops never see the buttons.
