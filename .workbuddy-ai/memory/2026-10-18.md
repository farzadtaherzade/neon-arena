# 2026-10-18

## Corner platforms + ramps: made the high ground a real feature

**Problem reported:** the map corners felt broken; ramps were decorative (not
worth having); mobs could not reach a player standing on a platform.

**Root causes found**
- `Arena.ramps()` never called `block()`/`addRamp()` — ramps were non-colliders,
  just boxes tilted 0.12 rad (~0.17 rise) against a 1.0 platform.
- `STEP_HEIGHT` was 1.0 and platforms 1.0 high, so the player stepped up from any
  side (ramp pointless), while enemies passed no `StepContext` and were blocked.
- Corner platforms sat 4.5 from the wall, leaving a 3-wide dead pocket behind.
- `Enemy.pos.y` was never updated and `EnemyView` ignored it, so mobs had no height.
- Melee was XZ-only, so mobs hit through the platform deck.

**Changes**
- `world/layout.ts`: `PLATFORM_H = 1.6`; platforms 6.2² at ±25 (outer face 28.1 =
  wall clamp − player radius, closing the pocket); `RAMPS` are
  `[x, z, width, length, upX, upZ]` with the high edge exactly on the platform face.
- `world/collision.ts`: new `Ramp` collider + `rampHeight()`; `addRamp()`;
  `groundHeight()` interpolates the slope; `resolveCircle()` blocks a ramp only
  where its surface exceeds the step allowance.
- `render/Arena.ts`: ramps are extruded wedges (mesh and collider from the same
  numbers) with cyan edge rails and a hazard threshold.
- `game/enemy.ts`: `EnemyWorld` gained `playerY`, `support()`, `ramps`, and
  `collide(..., feetY)`; enemies follow the ground with gravity (`followGround`)
  and detour via `route()`/`nearestRamp()` (aim at the ramp mouth, then its top);
  `ATTACK_RISE` gates melee by height.
- `game/player.ts`: "stick to slope" while walking down so ramps don't stutter.
- `game/config.ts`: `STEP_HEIGHT` 1 → 0.55; `ENEMY.STEP/CLIMB_RISE/ATTACK_RISE/RAMP_OFFSET/RAMP_ALIGN`.
- Bombs and XP orbs now take a Y so they rest on the deck instead of inside it.

**Verified:** `npm run typecheck`, `npm test` (134 passing, incl. new ramp/climb
tests), `npm run build`. E2E run was cancelled by the user before it finished.

**Note:** `npm run lint` fails repo-wide on CRLF line endings (pre-existing,
touches untouched files too); the edited files are Biome-format clean.

## Mouse-look glitch hardening (`src/ui/Input.ts`)

Reported symptom: intermittent "pointer jumps / teleports". Three defects found:

1. `LOOK_MAX` was 1500 → up to 198° of yaw in one event at `WEAPON.SENS`.
   `Player.look()`'s ±2048 clamp was dead code above it.
2. `mousemove` was gated on `this.locked`, which lags a lock loss by the 120 ms
   debounce — during that window the pointer is free and its deltas are measured
   from the real cursor, so every lock loss produced a view snap.
3. The click that re-acquires the pointer also set `firing = true`.

Fixes: `lookCaptured()` checks `document.pointerLockElement` directly;
`LOCK_WARMUP = 2` swallows the cursor-warp events after a lock is granted;
`LOOK_MAX` → 600 with a pure `lookDeltaOk()` (unit-tested); `mousedown` gated on
`inputCaptured()`. Headless (`?test`) keeps firing without pointer lock via a
third `Input` constructor arg, so the E2E is unaffected. Added
`__NEON.inputStats()` → `{ spikes, lockLosses, warmupDrops }` so a future report
can say whether a delta was rejected or the lock dropped.

Tests: 139 passing (new `tests/unit/input.test.ts`). AGENTS.md Trackpads section
now documents the trust model.

## Deck capture — making the platforms worth standing on

Design chosen by the user (asked explicitly): **hold-to-capture**, **timed
respawn**, **bomb magnet**, **rotate per wave**.

- `CAPTURE` config: HOLD_T 4 s, DECAY 2/s, COOLDOWN 40 s, HEAL 30 over HEAL_T 3 s,
  RADIUS 2.2, RISE 0.5.
- `src/game/capture.ts` — pure `CapturePoints`. The live deck is *derived*
  (`(wave-1) % 4`) so it can't desync from the HUD's wave counter (the wave can
  advance inside `WaveDirector`, not just `beginWave`). Progress drains off the
  pad instead of resetting; `feetY` check stops the floor below counting.
- `render/CapturePad.ts` — dark disc + amber ring + growing fill + a floating
  octahedron waypoint. **Not additive**: the deck top is an unlit cyan slab
  (`MAT.trim()`), and additive cyan on it blew the view to white. A light-shaft
  beam was tried first and had to go — standing inside it washed the screen and
  at range it read as a grey pillar.
- HUD: `#capture` bar under the crosshair, `HudModel.captureProgress/captureOn`.
- Enemy AI **reversed** from the previous task: mobs no longer climb. `route()`
  targets the ramp *mouth only*; sappers throw at the deck whenever the player
  is above `ATTACK_RISE`. `ENEMY.RAMP_ALIGN` removed (dead).
- `__NEON.teleportPlayer(x, z, y?)` and `__NEON.capture()` added for verification.

Verified in a real browser via Playwright: 60 HP → hold → `DECK SECURED` banner
→ cooldown 39.9 → HP climbs to 71+. Note SwiftShader runs the sim at ~1/4 real
time (MAX_DT clamp), so 4 s of sim takes ~16 s of wall clock.

Trade-off flagged to the user: this deliberately undoes "mobs come to you on the
platform" — the deck is now melee-safe and sappers are the counter.

## Map rebuild: 84×84 dense maze, gatehouses, alarm towers

User asked to remove the corner platforms, add alarm towers, and make a bigger
visually-stunning map. Design answers: **84×84**, **dense maze**, **cyan+amber+
magenta**, **beacon+siren+radar** alarms.

- `WORLD` 60 → 84 (HALF 42, WALL_H 6); new `WORLD.SPAWN_X/Z` = (0, 14) — the
  spawn plaza south of the reactor. `Player.reset()` now uses them.
- `PLATFORM_H` 1.6 → 2.4, ramps 6 long (≈22°). Decks moved to the **mid-edges**
  at ±35 (7×7), outer face 38.5, leaving a walkable 2.5 lane behind them.
- `OBSTACLES` is now `MAZE_QUADRANT` mirrored four ways (32 blocks) — edit the
  quadrant only, never the expanded list.
- `REACTOR` at the centre: solid 9×9×5.5, magenta rings + lit corner edges +
  additive core column + one magenta point light. Navigation landmark.
- `CapturePad` now owns the whole tower top: pad + mast (hazard collar) + beacon
  + thin column. Beacon: red when alarming, amber on the live deck, dim cyan
  otherwise — that is the wayfinding language.
- `game/alarm.ts` `TowerAlarm`: pure rising-edge detection with `ALARM.HOLD`.
  `Game.updateAlarm` does the spatial query; siren on the edge only; minimap
  pulses a red ring (`MapTower`).
- Spawn safety: `CollisionWorld.blockedAt()` + `WaveDirector.blocked`, so a maze
  never spawns a tank inside a wall. Ring 30±6, MIN_DIST 20.

Visual iterations found by screenshotting the build:
- Additive light-shaft beam washed the screen to white when standing in it → the
  beacon column is thin (0.22) and the pad uses normal blending.
- 32 full-width hazard tops read as one yellow slab from above → inset bronze
  cap leaves a yellow rim.
- Dark mast vanished against the sky (beacon looked detached) → lighter metal +
  hazard collar.
- Reactor was a black void → magenta corner edges.

E2E needed three fixes for a maze map (all harness, not game):
1. `teleportEnemies(22)` hid targets behind walls → `faceEnemies` now lines them
   up along the player's yaw, and the spec aims south down the plaza first.
2. Geometry-count leak check false-positived: an 84-unit map uploads static
   geometry lazily, so `warmUp` now sweeps the view 360° before measuring.
3. HP assertions were absolute; now they wait for the spawn queue to drain and
   compare a delta with the mobs parked.
